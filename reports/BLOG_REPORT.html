1) Tóm tắt

Dự án xây dựng một chương trình console trên Windows để đọc hoặc tự sinh mê cung và dùng DFS để tìm đường từ S tới E. Chương trình hỗ trợ:

  • Chọn độ khó (10×10, 20×20, 30×30)
  • Chọn tốc độ animation
  • Chọn chế độ hiển thị (giảm “rối” khi vẽ visited)
  • Hiển thị màu và status line Step/X/Y như “debug log”
Điểm nhấn báo cáo
Chương trình được chia module (SV1/UI, SV2/IO, SV3/Core) và có luồng demo rõ ràng; phần xử lý thanh ghi/calling convention được dùng làm điểm chứng minh “cấp độ hợp ngữ”.

2) Mục tiêu & phạm vi

Mục tiêu

  • Xây dựng solver DFS chạy ổn định, không phụ thuộc thư viện ngoài.
  • UI dễ quan sát: có màu, có trạng thái tiến trình, có chế độ hiển thị.
  • Module hoá để mỗi sinh viên báo cáo độc lập.

Phạm vi

  • Nền tảng: Win32 32-bit (PE32), không phải DOS 16-bit.
  • Giao diện: console text (không GUI).
  • Thuật toán: DFS (không tối ưu đường ngắn nhất như BFS/A*).

3) Công nghệ & build

Toolchain

  • NASM: -f win32
  • GCC 32-bit: -m32
  • WinAPI console: WriteConsoleA, SetConsoleCursorPosition, FillConsoleOutput*

Lệnh build

cd "Asm-maze-solver-win32-nasm"
.\build.bat
.\maze_solver.exe

Build script: build.bat

5) Mô hình dữ liệu

Mê cung lưu trong mảng 1 chiều maze, index theo công thức:

index = y * cols + x

Routine tính index: MAIN_GetIndex

Mã hoá cell trong bộ nhớ

  • '1': wall
  • '0': path
  • 'S': start
  • 'E': end
  • 'V': visited (DFS nội bộ)

Mapping khi vẽ lên màn hình

  • '1' → #
  • '0' → .
  • S/E giữ nguyên

Sơ đồ memory (khái niệm)

Sơ đồ này đang mô tả nhóm biến/array được cấp phát tĩnh trong section .data của main.asm (ví dụ maze, stack_x, stack_y, rows/cols, dfs_steps). Core/UI chỉ “dùng chung” các vùng nhớ đó.

6) UI Console (WinAPI)

WinAPI sử dụng

  • In text: WriteConsoleA
  • Đọc phím: ReadConsoleA
  • GotoXY: SetConsoleCursorPosition
  • Clear: FillConsoleOutputCharacterA + FillConsoleOutputAttribute
  • Màu: SetConsoleTextAttribute
  • Animation: Sleep

Vì sao phải “giữ thanh ghi” trong UI

Core DFS dùng EBX/ECX làm chỉ số (x/y) và loop. Nếu UI không preserve đúng, giá trị chỉ số bị phá, dẫn đến vẽ sai/hang.

Code dẫn chứng
UI giữ thanh ghi (push/pop) khi vẽ: UI_DrawChar

Dọn layout để không “lem chữ”

Để status/legend cập nhật liên tục mà không để lại ký tự thừa, chương trình clear cả dòng trước khi vẽ lại.

UI_ClearLine:
    call _GetConsoleScreenBufferInfo@8
    movzx ecx, word [ebp-22]
    movzx eax, word [coord_y]
    shl eax, 16
    call _FillConsoleOutputCharacterA@20
    call _FillConsoleOutputAttribute@20

Nguồn: UI_ClearLine

Status line (debug log)

Mỗi bước DFS update 1 dòng: Step:#### X:## Y:##. Dòng này đặt ở hàng rows + 3 để không đè lên mê cung.

Nguồn: DFS_UpdateStatus

8) Thuật toán DFS

Ý tưởng

DFS duyệt sâu theo 4 hướng. Để không dùng hardware stack cho toàn trạng thái, chương trình dùng “software stack” với 2 mảng stack_x/stack_y.

Routine chính: DFS_Solve

Sơ đồ DFS (rút gọn)

flowchart TD
  L0[stack_top == 0 ?] -->|yes| END[Return]
  L0 -->|no| POP["DFS_Pop -> (x,y)"]
  POP --> CELL[Read maze cell]
  CELL -->|E| FOUND[Stop]
  CELL -->|Wall/Visited| L0
  CELL -->|Path/S| MARK[Mark visited 'V']
  MARK --> STATUS[Update status line]
  STATUS --> DRAW[Draw @ and maybe *]
  DRAW --> N1[Push neighbors R,D,L,U if valid]
  N1 --> L0

Chế độ hiển thị (giảm rối)

Display mode giúp giảng viên thấy rõ “cường độ vẽ” khác nhau:

  • Minimal: chỉ @ chạy, không để lại *
  • Normal: chỉ để lại * mỗi 4 bước
  • Dense: luôn để lại *
DFS_Draw:
    inc dword [dfs_steps]
    call DFS_UpdateStatus
    mov al, [dfs_display_mode]
    cmp al, 0
    je DFS_DrawMinimal
    cmp al, 1
    je DFS_DrawNormal
    jmp DFS_DrawDense

Nguồn: DFS_Draw selection

Kiểm tra biên đúng dấu (signed)

Toạ độ có thể âm khi dec. Nếu dùng nhảy unsigned sẽ dễ “underflow thành số lớn”. Vì vậy code dùng test + js để bắt âm.

Nguồn: MAIN_IsValid

9) Sinh mê cung ngẫu nhiên

Chế độ random có đảm bảo tồn tại đường đi bằng cách: (1) fill tường toàn bộ, (2) carve một path từ (1,1) đến (cols-2,rows-2), (3) mở thêm ngẫu nhiên một số ô.

flowchart TD
  A[Fill all '1'] --> B[Carve guaranteed path '0']
  B --> C[Randomly open remaining walls]
  C --> D["Write 'S' at (1,1)"]
  D --> E["Write 'E' at (cols-2,rows-2)"]

Nguồn: MAIN_GenerateRandomMaze

11) Kết quả & hạn chế

Kết quả

  • Chạy ổn định, có menu độ khó/tốc độ/chế độ hiển thị.
  • UI rõ ràng: màu + legend gọn + status line.
  • Module hoá phù hợp báo cáo nhóm.

Hạn chế

  • DFS không đảm bảo đường đi ngắn nhất.
  • Chưa có “highlight đường nghiệm cuối” (backtracking path) để trình diễn đẹp hơn.
  • Bản Win32 không chạy trên emu8086 (khác nền tảng).
