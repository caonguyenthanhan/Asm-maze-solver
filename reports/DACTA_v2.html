1. Giới thiệu đồ án

Chương trình mô phỏng trò chơi mê cung chạy trên Windows Console, lập trình hoàn toàn bằng Assembly (NASM, 32-bit). Hệ thống có menu chức năng, cho phép nạp cấu trúc mê cung từ file văn bản (.txt) hoặc sinh mê cung ngẫu nhiên.

Điểm nhấn kỹ thuật là AI tự động tìm đường từ điểm bắt đầu (S) đến đích (E) bằng thuật toán Duyệt theo chiều sâu (DFS – Depth-First Search), dùng ngăn xếp phần mềm (stack_x/stack_y) để dò đường, đánh dấu ô đã thăm (V) và tự quay lui khi gặp ngõ cụt. Quá trình giải hiển thị theo từng bước (animation) với màu sắc.

2. Tổng quan hệ thống

Hệ thống chia 3 module, tích hợp qua main.asm bằng %include:

  • UI (UI/ui.asm): Render console, di chuyển con trỏ, đặt màu, đọc phím, in chuỗi/số.
  • File I/O (IO/file.asm): Mở/đọc file, bỏ BOM, chuẩn hóa CR/LF, tự xác định số dòng/cột, phát hiện lỗi đọc cơ bản.
  • Core (core/core.asm): Validate mê cung, tìm S/E, thuật toán DFS, sinh mê cung ngẫu nhiên, đếm thống kê.

main.asm chứa _main, toàn bộ chuỗi .data, menu và các màn hình.

4. Kiến thức môn học áp dụng

Nhóm kiến thứcÁp dụng thực tế
Thanh ghi CPUEAX: giá trị trả về (success/fail, errorCode). EBX/ECX: chỉ số cột/dòng. EDX/EDI: tọa độ tạm trong DFS. ESI: con trỏ duyệt maze. ESP/EBP: khung stack push ebp/mov ebp,esp ... leave/ret.
Vùng .data/.bss/.text.data: chuỗi menu/hướng dẫn/lỗi, mảng maze, stack_x/y, biến trạng thái. .bss: file_size, file_handle, bytes_read. .text: các thủ tục.
MOV, LEA, PUSH, POPMOV nạp/ghi biến và ký tự ra màn hình. PUSH/POP truyền tham số WinAPI (stdcall) và bảo toàn thanh ghi.
ADD, SUB, INC, DEC, MUL/IMULINC/DEC chỉ số vòng lặp và con trỏ. MUL tính index = row*cols + col. IMUL trong LCG sinh ngẫu nhiên.
CMP + nhảySo sánh phím menu, kiểm tra biên mê cung, phân loại ô, rẽ nhánh errorCode.
Vòng lặpIn menu, duyệt ký tự file, validate, vẽ mê cung, vòng lặp DFS.
Stack & calling conventionWinAPI stdcall tự dọn stack; chương trình PUSH đúng thứ tự tham số.
File I/OCreateFileA/ReadFile/CloseHandle; xử lý lỗi mở file, file rỗng, dòng không đều.
Thuật toán DFSTừ S thử 4 hướng, đẩy software stack, đánh dấu V, quay lui khi cụt, dừng khi gặp E.
Mảng 1D mô phỏng 2Dmaze là mảng byte cols*rows; truy cập ô qua row*cols+col.

7. Bảng mã lỗi (errorCode) — FR-09

MãHằngNguồnThông báo
0——Hợp lệ, cho phép chạy DFS
1err_1FILE_ReadMaze (mở file thất bại)Khong tim thay file me cung.
2err_2FILE_ReadMaze (file_size = 0)File me cung rong.
3err_3MAIN_ValidateMaze (ký tự lạ)File me cung sai dinh dang.
4err_4MAIN_ValidateMaze (không có S)Khong tim thay diem bat dau S.
5err_5MAIN_ValidateMaze (không có E)Khong tim thay diem ket thuc E.
6err_6MAIN_ValidateMaze (cols*rows > 1600)Me cung vuot qua kich thuoc cho phep.
7err_7FILE_ReadMaze (dòng không đều)Cau truc me cung khong hop le.
Ký tự hợp lệ: '0' '1' 'S' 'E' ' '. Mọi ký tự khác ⇒ errorCode 3.

sequenceDiagram
    participant M as main (do_solve_file)
    participant F as FILE_ReadMaze

    W-->>F: noi dung file
    F->>F: bo BOM, dem cols/rows, check ragged, strip CRLF

        alt EAX = 0
            M->>M: show_error (err_3/4/5/6)
        else EAX = 1
            M->>M: ve me cung + chay DFS
        end
    end
